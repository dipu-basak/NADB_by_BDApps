# Notes — Flutter + Cloud Firestore

A simple **Notes Management Application** built with Flutter and Cloud Firestore.
It demonstrates how a Flutter app performs **CRUD** (Create, Read, Update,
Delete) against a real cloud database, with the UI updating live as data
changes.

Built as part of the National App Development Bootcamp (BDApps). This app lives
in the `notes_app/` subdirectory of this repository.

## Features

- **Create** — add a note with a title and description
- **Read** — all notes stream live from Firestore, newest first
- **Update** — tap any note to edit its title and description
- **Delete** — swipe a note to delete it (with confirmation), or use the
  delete button inside the editor
- **Live sync** — the list updates in real time when the database changes
- **Validation** — title and description are required
- **Light & dark theme** — follows the system setting
- **Testable architecture** — screens talk to a `NotesRepository` interface, so
  tests use an in-memory fake instead of Firestore

## Screens

| Screen | What it does |
| --- | --- |
| **Notes List** | Streams every note from the `notes` collection. Shows a friendly empty state, an error state with retry, and note cards (title, description, last-updated date). FAB creates a new note. Swipe left to delete. |
| **Add / Edit Note** | A form used for both creating and editing. Pre-fills the existing note in edit mode and saves changes back to Firestore. |

## Firebase setup (required once)

The app reads `lib/firebase_options.dart`, which is normally generated by the
FlutterFire CLI. The file currently contains **placeholder values** — the app
will start but fail to connect until you complete these steps:

1. **Create a Firebase project** at <https://console.firebase.google.com>.
2. **Add your app** to the project:
   - *Android:* package name `com.example.notes_app`
   - *iOS:* bundle id `com.example.notesApp`
   - *Web:* any name
3. **Enable Cloud Firestore** (Build → Firestore Database → Create database).
   Choose **production mode**, then set the rules below (or start in test mode).
4. **Install the Firebase + FlutterFire CLIs:**
   ```sh
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   firebase login
   ```
5. **Generate the config file** from this project's root:
   ```sh
   flutterfire configure
   ```
   Select your Firebase project and the platforms you support. This rewrites
   `lib/firebase_options.dart` with real credentials.
6. **Apply the security rules** (test mode — open access, fine for learning):
   ```sh
   firebase deploy --only firestore:rules
   ```
   Or paste `firestore.rules` in the Firebase console (Firestore → Rules).

## Run it

Requires the [Flutter SDK](https://docs.flutter.dev/get-started/install).

```sh
flutter pub get     # fetch dependencies
flutter run         # run on a device/emulator (or -d chrome)
flutter test        # run the unit + widget tests
```

## How the CRUD maps to the code

| Operation | Where |
| --- | --- |
| Create | `FirestoreNotesRepository.addNote` → `_notes.add({...})` |
| Read (live) | `FirestoreNotesRepository.watchNotes` → `orderBy('createdAt').snapshots()` |
| Update | `FirestoreNotesRepository.updateNote` → `doc(id).update({...})` |
| Delete | `FirestoreNotesRepository.deleteNote` → `doc(id).delete()` |

## Tests

- `test/note_test.dart` — unit tests for the `Note` model
- `test/widget_test.dart` — widget tests covering create, edit, delete
  (swipe + confirm), validation, and the empty state — all against an
  in-memory `FakeNotesRepository`, so no Firebase is needed to run them
